## 二、当前设计结论

1. 一个机构一个数据库，库内不重复保存 `institution_id`。
2. 核心关系、状态、时间、顺序和分值使用关系型字段。
3. 选项、量规、联系方式和低频属性使用JSON，避免过早拆表。
4. 一行只表达一个业务事实；无明确业务触发条件不增加表。
5. 业务主链为：人员 → 班级 → 内容 → 任务 → 提交 → 逐题答案 → 反馈。
6. `schema_version` 独立治理，不计入10张业务表。

## 五、问题与修复记录

1. 初次建库缺少 `answer` 表：MySQL 8.4需要保护该标识符，已统一改为反引号形式。
2. `graded_by` 同时参与检查约束和 `ON DELETE SET NULL` 外键动作，MySQL 8.4拒绝创建；已改为 `ON DELETE RESTRICT`，保留评分审计记录。
3. `SOURCE` 默认遇错继续执行，可能留下错误版本号；2.0.1迁移已改为仅在表和视图都存在时登记版本。
4. 本机MySQL socket为 `/private/tmp/mysql.sock`，不是默认 `/tmp/mysql.sock`。
